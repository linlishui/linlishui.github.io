SwiftUI基础入门：从状态驱动界面开始

SwiftUI 是 Apple 提供的声明式 UI 框架。和 UIKit 里手动创建控件、修改属性、维护页面层级不同，SwiftUI 更强调“界面是状态的函数”：状态变了，界面自动重新计算并刷新。 如果已经有 Kotlin、Android 或 Compose 经验，可以把 SwiftUI 先理解为 Apple 平台上的声明式 UI 方案。它和 Jetpack Compose 很像，都不是简单的 XML 或 View 替代品，而是一套围绕状态、组合和数据流设计的 UI 编程模型。 SwiftUI 解决什么问题 在 UIKit 中，常见写法是先拿到控件，再手动更新控件状态。 label.text = user.name button.isEnabled = !isLoading loadingView.isHidden = !isLoading 这种方式本身没有问题，但页面复杂后，状态和 UI 很容易分散在多个地方。比如加载中、加载成功、加载失败、空列表、按钮是否可点，都需要开发者手动维护。 SwiftUI 的思路是反过来：先描述不同状态下界面应该长什么样，然后让框架根据状态变化刷新界面。 struct ContentView: View { @State private var isLoading = false var body: some View { VStack { if isLoading { ProgressView() } else { Text("加载完成") } Button("加载") { isLoading = true } } } } 这里没有手动隐藏 ProgressView，也没有手动修改 Text。只要 isLoading 变化，body 会重新计算，界面会随之更新。 View 是什么 SwiftUI 中的页面和组件通常是一个 struct，并且遵守 View 协议。 ...
