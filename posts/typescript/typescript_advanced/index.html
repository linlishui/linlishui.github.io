上一篇入门文章已经覆盖了基础类型、函数、对象、interface、type、联合类型和可空处理。继续往下学 TypeScript，重点不是记更多语法，而是学会把类型用在真实代码里：接口响应、状态结构、异步结果和公共函数都应该有清晰的类型边界。

模块导入与文件引用#

TypeScript 支持用 export 暴露变量、函数或类型，再用 import 在其他文件中引用：

// user.ts
export type User = {
  id: number;
  name: string;
};

export function getUserName(user: User): string {
  return user.name;
}

// main.ts
import { getUserName, type User } from "./user";

const user: User = {
  id: 1,
  name: "Tom",
};

console.log(getUserName(user));

和 Kotlin 按包名导入不同，TypeScript 默认更多是按文件路径导入。"./user" 表示同级目录下的 user.ts，通常可以省略 .ts 后缀。

如果只引用类型，推荐使用 import type：

import type { User } from "./user";

大型项目里也常见路径别名，例如 @/models/user，但这需要在 tsconfig.json 里配置 baseUrl 和 paths。

泛型是什么#

泛型可以简单理解成：把类型也作为参数传进去。

它解决的核心问题是：代码逻辑可以复用，但类型信息不能丢。

function wrap<T>(value: T): T[] {
  return [value];
}

const names = wrap("hello"); // string[]
const ids = wrap(100);       // number[]

如果不用泛型，很容易退回到 any：

function wrap(value: any): any[] {
  return [value];
}

这段代码虽然能运行，但调用方拿不到准确类型提示。

泛型最常见的使用场景是接口响应：

type ApiResponse<T> = {
  code: number;
  message: string;
  data: T;
};

type User = {
  id: number;
  name: string;
};

const response: ApiResponse<User> = {
  code: 0,
  message: "ok",
  data: {
    id: 1,
    name: "Tom",
  },
};

可以先记住一句话：泛型不是为了把类型写复杂，而是为了保留“输入、输出、数据结构之间的类型关系”。

类型收窄#

联合类型很常见，但使用联合类型时，不能直接访问某个类型独有的属性。需要先判断，再使用。

1. typeof#

function formatId(id: string | number): string {
  if (typeof id === "number") {
    return id.toFixed(0);
  }

  return id.toUpperCase();
}

2. in#

对象联合类型可以用 in 判断字段是否存在：

type User = {
  id: number;
  name: string;
};

type Admin = {
  id: number;
  role: string;
};

function printAccount(account: User | Admin) {
  if ("role" in account) {
    console.log(account.role);
  } else {
    console.log(account.name);
  }
}

3. 判别字段#

如果多个状态结构差异明显，更推荐增加固定字段：

type PageState =
  | { status: "loading" }
  | { status: "success"; data: string[] }
  | { status: "error"; message: string };

function render(state: PageState) {
  switch (state.status) {
    case "loading":
      return "加载中";
    case "success":
      return state.data.join(",");
    case "error":
      return state.message;
  }
}

这种写法比到处判断字段是否存在更稳定，适合页面状态、任务状态、消息类型等场景。

常用工具类型#

TypeScript 内置了很多工具类型，但日常项目里不需要一次记完。先掌握下面几个就够用。

1. Record#

Record<K, V> 用来描述一组固定 key 对应同一种 value 的结构。

type Role = "admin" | "user" | "guest";

const roleNames: Record<Role, string> = {
  admin: "管理员",
  user: "普通用户",
  guest: "访客",
};

它适合做枚举值到文案、配置、处理函数的映射。如果少写一个 key，TypeScript 会提示错误。

2. Partial#

Partial<T> 会把字段都变成可选字段，常用于更新参数。

type User = {
  id: number;
  name: string;
  email: string;
};

function updateUser(id: number, patch: Partial<User>) {
  console.log(id, patch);
}

updateUser(1, {
  name: "Jerry",
});

3. Pick 和 Omit#

Pick<T, K> 是从类型中挑字段，Omit<T, K> 是从类型中排除字段。

type User = {
  id: number;
  name: string;
  email: string;
  password: string;
};

type UserCard = Pick<User, "id" | "name">;
type PublicUser = Omit<User, "password">;

它们适合从完整数据结构里拆出列表项、卡片、公开信息、表单参数等类型。

4. Awaited#

Awaited<T> 用来拿到 Promise 解析后的类型，异步代码里很实用。

async function getUser() {
  return {
    id: 1,
    name: "Tom",
  };
}

type User = Awaited<ReturnType<typeof getUser>>;

这里 User 的类型就是 getUser() 真正返回的数据类型，而不是 Promise<...>。 其中 ReturnType 用来取函数返回值类型，Awaited 再把 Promise 包住的结果拆出来。

as const 保留字面量类型#

普通对象里的字符串值通常会被推断成 string，如果希望保留更精确的字面量类型，可以使用 as const。

const statusMap = {
  loading: "加载中",
  success: "成功",
  error: "失败",
} as const;

type Status = keyof typeof statusMap;

这里的 Status 是 "loading" | "success" | "error"，适合用在状态值、事件名、路由名、固定配置这类场景。

异步常用技巧#

TypeScript 的异步语法来自 JavaScript，核心还是 Promise、async、await。TypeScript 主要负责把异步结果的类型表达清楚。

1. async 函数返回 Promise#

async function getName(): Promise<string> {
  return "Tom";
}

即使函数里直接 return "Tom"，async 函数的返回值也会被包装成 Promise<string>。

调用时需要 await：

const name = await getName();

2. 并发请求用 Promise.all#

如果多个异步任务互不依赖，不要一个一个 await：

const user = await fetchUser();
const orders = await fetchOrders();

这会串行执行。更常见的并发写法是：

const [user, orders] = await Promise.all([
  fetchUser(),
  fetchOrders(),
]);

Promise.all 适合“全部成功才继续”的场景。

3. 部分失败可用 Promise.allSettled#

如果不希望一个请求失败就中断全部任务，可以用 Promise.allSettled：

const results = await Promise.allSettled([
  fetchUser(),
  fetchOrders(),
]);

results.forEach((result) => {
  if (result.status === "fulfilled") {
    console.log(result.value);
  } else {
    console.log(result.reason);
  }
});

它返回的结果天然适合用判别字段 status 做类型收窄。

4. 循环里的 await 要看场景#

下面这种写法会按顺序执行：

for (const id of ids) {
  await fetchUser(id);
}

如果每个请求必须依赖上一个结果，这样没问题。 如果它们互不依赖，可以改成并发：

await Promise.all(ids.map((id) => fetchUser(id)));

这里的关键不是“循环里不能写 await”，而是要分清任务是否真的需要串行。

5. 异步错误要在边界处理#

async function loadPage() {
  try {
    const user = await fetchUser();
    return user;
  } catch (error) {
    if (error instanceof Error) {
      console.log(error.message);
    }

    throw error;
  }
}

catch 里的 error 不应该直接当成 Error 使用，先判断会更稳妥。

断言要少用#

类型断言 as 的意思是：“我确定它是这个类型”。它只影响编译期，不会改变运行时数据。

const input = document.getElementById("username") as HTMLInputElement;
console.log(input.value);

这种写法在 DOM 场景里常见，但不要把断言当成校验：

const user = JSON.parse(text) as User;

这只能让 TypeScript 相信 user 是 User，不能保证接口数据真的符合结构。关键数据仍然需要运行时判断。

如果一个值来源不确定，优先用 unknown，再收窄：

function parseName(value: unknown): string {
  if (typeof value === "string") {
    return value;
  }

  return "unknown";
}

常见坑点#

1. 类型写得太宽#

let status: string = "loading";

如果状态只有几种，更推荐写成字面量联合类型：

let status: "loading" | "success" | "error" = "loading";

2. 到处使用 any#

any 会让后续代码失去类型保护。接口边界、历史代码迁移时可以临时使用，但不要让它扩散到核心类型里。

3. 混淆类型检查和运行时校验#

type、interface、as 都不会生成运行时校验逻辑。接口数据、用户输入、配置文件这类外部数据，不能只靠 TypeScript 类型保证安全。

小结#

TypeScript 进阶不等于写复杂类型。真正实用的方向是：

  • 用 export 和 import 管理不同文件之间的引用
  • 用泛型保留类型关系
  • 用类型收窄安全处理联合类型
  • 用 Record、Partial、Pick、Omit、Awaited 复用已有类型
  • 用 as const 保留固定配置里的字面量类型
  • 用 Promise.all、Promise.allSettled 管理异步任务
  • 少用 any 和盲目断言，把不确定数据放在边界处理

类型写得清楚，比类型写得炫技更重要。先把接口响应、页面状态、异步结果和公共函数的类型边界整理好，就能减少很多低级错误。
