SwiftUI列表与导航基础

上一篇 SwiftUI 文章重点讲“状态驱动界面”。这篇继续往实际页面推进，聚焦两个最常见的能力：列表和导航。

大多数 App 都离不开这类页面：展示一组数据，点击某一项进入详情页。SwiftUI 中对应的核心组件是 List、ForEach、NavigationStack 和 NavigationLink。

这篇文章的目标不是罗列所有 API，而是写清楚一条常见数据流：

ViewModel 加载数据 -> View 根据状态切换 UI -> List 渲染数据 -> NavigationLink 进入详情

数据模型与稳定 id#

列表页面首先需要一个数据模型。比如文章列表：

struct Article: Identifiable, Hashable {
    let id: UUID
    let title: String
    let summary: String
    let author: String
}

这里同时遵守了两个协议：

  • Identifiable：让 List 能识别每一项
  • Hashable：后面做基于值的导航时会用到

Identifiable 很重要。SwiftUI 需要通过稳定的 id 判断哪些行被新增、删除或更新。

如果数据来自服务端，通常应该直接使用服务端返回的业务 id：

struct Article: Identifiable, Hashable {
    let id: String
    let title: String
    let summary: String
}

不要随手用数组下标当作长期稳定 id。插入、删除、排序后，下标会变化，容易导致列表刷新异常。

用 List 展示集合数据#

一个最小列表可以这样写：

struct ArticleListView: View {
    let articles: [Article]

    var body: some View {
        List(articles) { article in
            Text(article.title)
        }
    }
}

这段代码表达的是：对 articles 中的每个元素生成一行 View。

如果列表结构很简单，List(items) { item in ... } 就够了。

如果列表中还有分组、头部、静态项混排，通常显式使用 ForEach：

List {
    Section("文章") {
        ForEach(articles) { article in
            Text(article.title)
        }
    }

    Section("操作") {
        Button("刷新") {
            print("reload")
        }
    }
}

入门阶段可以先这样判断：

  • 简单数据列表：List(items) { item in ... }
  • 分组、头部、静态项混排：List { Section { ForEach(...) } }

拆分列表行 View#

真实页面里，一行通常不只是一个标题。可以把行拆成单独的 View。

struct ArticleRowView: View {
    let article: Article

    var body: some View {
        VStack(alignment: .leading, spacing: 6) {
            Text(article.title)
                .font(.headline)
                .lineLimit(1)

            Text(article.summary)
                .font(.subheadline)
                .foregroundStyle(.secondary)
                .lineLimit(2)

            Text(article.author)
                .font(.caption)
                .foregroundStyle(.secondary)
        }
        .padding(.vertical, 4)
    }
}

列表中使用：

List(articles) { article in
    ArticleRowView(article: article)
}

拆出行 View 的好处是列表页面更清楚，行样式也更容易复用和预览。

处理加载、错误和空状态#

列表页面不是只有“有数据”这一种状态。常见状态至少有四类：

  • 加载中
  • 加载失败
  • 空列表
  • 有数据

可以先用一个 ViewModel 管理这些状态：

@MainActor
final class ArticleListViewModel: ObservableObject {
    @Published var articles: [Article] = []
    @Published var isLoading = false
    @Published var errorMessage: String?

    func load() async {
        isLoading = true
        errorMessage = nil

        do {
            articles = [
                Article(
                    id: UUID(),
                    title: "SwiftUI 列表基础",
                    summary: "学习 List、ForEach 和列表行拆分",
                    author: "Tom"
                ),
                Article(
                    id: UUID(),
                    title: "SwiftUI 导航基础",
                    summary: "学习 NavigationStack 和 NavigationLink",
                    author: "Jerry"
                )
            ]
        } catch {
            errorMessage = "加载文章失败"
        }

        isLoading = false
    }
}

页面根据状态切换 UI：

struct ArticleListContentView: View {
    let isLoading: Bool
    let errorMessage: String?
    let articles: [Article]

    var body: some View {
        Group {
            if isLoading {
                ProgressView()
            } else if let message = errorMessage {
                ContentUnavailableView(message, systemImage: "exclamationmark.triangle")
            } else if articles.isEmpty {
                ContentUnavailableView("暂无文章", systemImage: "doc.text")
            } else {
                List(articles) { article in
                    ArticleRowView(article: article)
                }
            }
        }
    }
}

不要把空状态硬塞成列表中的一行。空状态、错误状态和加载状态通常是页面状态，不是列表数据本身。

用 NavigationStack 建立导航容器#

NavigationStack 是 SwiftUI 中管理页面跳转的常用容器。它表示一个导航栈：从列表页进入详情页，再从详情页返回列表页。

struct ArticleListPage: View {
    let articles: [Article]

    var body: some View {
        NavigationStack {
            List(articles) { article in
                ArticleRowView(article: article)
            }
            .navigationTitle("文章")
        }
    }
}

navigationTitle 设置当前页面标题。通常每个需要导航栏标题的页面都应该设置它。

新代码建议优先使用 NavigationStack。老项目里可能还会看到 NavigationView，它是较早的导航 API。维护旧代码时需要认识它，但新写 SwiftUI 页面时可以优先从 NavigationStack 开始。

用 NavigationLink 进入详情页#

先定义一个详情页：

struct ArticleDetailView: View {
    let article: Article

    var body: some View {
        ScrollView {
            VStack(alignment: .leading, spacing: 12) {
                Text(article.title)
                    .font(.title)
                    .bold()

                Text(article.author)
                    .font(.subheadline)
                    .foregroundStyle(.secondary)

                Divider()

                Text(article.summary)
                    .font(.body)
            }
            .padding()
        }
        .navigationTitle("详情")
    }
}

在列表中使用 NavigationLink：

NavigationStack {
    List(articles) { article in
        NavigationLink {
            ArticleDetailView(article: article)
        } label: {
            ArticleRowView(article: article)
        }
    }
    .navigationTitle("文章")
}

这里的 NavigationLink 同时描述了两件事：

  • 当前列表行展示什么
  • 点击后跳到哪个详情页面

这种写法适合简单列表详情页，直观、代码少。

基于值的导航#

页面复杂后，可以使用基于值的导航，把“点击了什么值”和“这个值对应哪个页面”分开。

NavigationStack {
    List(articles) { article in
        NavigationLink(value: article) {
            ArticleRowView(article: article)
        }
    }
    .navigationDestination(for: Article.self) { article in
        ArticleDetailView(article: article)
    }
    .navigationTitle("文章")
}

这种写法有两个特点：

  • NavigationLink(value:) 只负责把某个值放进导航系统
  • navigationDestination(for:) 统一声明这种值应该跳到哪个页面

如果页面里有多种跳转目标，这种方式会更清楚。

.navigationDestination(for: Article.self) { article in
    ArticleDetailView(article: article)
}
.navigationDestination(for: Author.self) { author in
    AuthorDetailView(author: author)
}

入门阶段可以先这样判断：

  • 简单列表跳详情：直接在 NavigationLink 中写目标 View
  • 多种目标页、复杂路径：使用 value + navigationDestination

一个完整的列表详情页示例#

把前面的内容组合起来，一个完整的列表详情页大致如下。

import SwiftUI

struct Article: Identifiable, Hashable {
    let id: UUID
    let title: String
    let summary: String
    let author: String
}

@MainActor
final class ArticleListViewModel: ObservableObject {
    @Published var articles: [Article] = []
    @Published var isLoading = false
    @Published var errorMessage: String?

    func load() async {
        isLoading = true
        errorMessage = nil

        do {
            articles = [
                Article(
                    id: UUID(),
                    title: "SwiftUI 列表基础",
                    summary: "学习 List、ForEach 和列表行拆分",
                    author: "Tom"
                ),
                Article(
                    id: UUID(),
                    title: "SwiftUI 导航基础",
                    summary: "学习 NavigationStack 和 NavigationLink",
                    author: "Jerry"
                )
            ]
        } catch {
            errorMessage = "加载文章失败"
        }

        isLoading = false
    }
}

struct ArticleListPage: View {
    @StateObject private var viewModel = ArticleListViewModel()

    var body: some View {
        NavigationStack {
            Group {
                if viewModel.isLoading {
                    ProgressView()
                } else if let message = viewModel.errorMessage {
                    ContentUnavailableView(message, systemImage: "exclamationmark.triangle")
                } else if viewModel.articles.isEmpty {
                    ContentUnavailableView("暂无文章", systemImage: "doc.text")
                } else {
                    List(viewModel.articles) { article in
                        NavigationLink(value: article) {
                            ArticleRowView(article: article)
                        }
                    }
                }
            }
            .navigationTitle("文章")
            .navigationDestination(for: Article.self) { article in
                ArticleDetailView(article: article)
            }
            .task {
                await viewModel.load()
            }
        }
    }
}

struct ArticleRowView: View {
    let article: Article

    var body: some View {
        VStack(alignment: .leading, spacing: 6) {
            Text(article.title)
                .font(.headline)
                .lineLimit(1)

            Text(article.summary)
                .font(.subheadline)
                .foregroundStyle(.secondary)
                .lineLimit(2)

            Text(article.author)
                .font(.caption)
                .foregroundStyle(.secondary)
        }
        .padding(.vertical, 4)
    }
}

struct ArticleDetailView: View {
    let article: Article

    var body: some View {
        ScrollView {
            VStack(alignment: .leading, spacing: 12) {
                Text(article.title)
                    .font(.title)
                    .bold()

                Text(article.author)
                    .font(.subheadline)
                    .foregroundStyle(.secondary)

                Divider()

                Text(article.summary)
                    .font(.body)
            }
            .padding()
        }
        .navigationTitle("详情")
    }
}

这段代码串起了完整流程：

ViewModel 加载 articles
-> ArticleListPage 根据状态显示加载、空状态或列表
-> List 渲染 ArticleRowView
-> NavigationLink(value:) 进入 ArticleDetailView

下拉刷新与分页加载#

列表页通常还会遇到刷新和分页。

下拉刷新可以使用 .refreshable：

List(viewModel.articles) { article in
    NavigationLink(value: article) {
        ArticleRowView(article: article)
    }
}
.refreshable {
    await viewModel.load()
}

首次进入页面加载，可以使用 .task：

.task {
    await viewModel.load()
}

分页加载通常在某一行出现时触发：

List(viewModel.articles) { article in
    ArticleRowView(article: article)
        .onAppear {
            if article == viewModel.articles.last {
                Task {
                    await viewModel.loadMore()
                }
            }
        }
}

这里没有展开完整分页实现，因为真实分页还需要处理 page、hasMore、isLoadingMore、重复请求保护和错误重试。入门阶段先理解触发位置即可。

删除与移动#

SwiftUI 的 List 支持常见编辑操作，比如删除。

struct Todo: Identifiable {
    let id: UUID
    var title: String
}

struct TodoListView: View {
    @State private var todos: [Todo] = [
        Todo(id: UUID(), title: "学习 SwiftUI"),
        Todo(id: UUID(), title: "写一个列表页面")
    ]

    var body: some View {
        List {
            ForEach(todos) { todo in
                Text(todo.title)
            }
            .onDelete { offsets in
                todos.remove(atOffsets: offsets)
            }
        }
        .toolbar {
            EditButton()
        }
    }
}

移动列表项：

List {
    ForEach(todos) { todo in
        Text(todo.title)
    }
    .onMove { source, destination in
        todos.move(fromOffsets: source, toOffset: destination)
    }
}

这类操作适合本地数据或已经有明确更新逻辑的业务数据。真实项目里删除后通常还要同步服务端，并处理失败回滚。

程序化导航#

有些跳转不是用户点击某一行触发的，比如登录成功后进入首页、保存成功后进入详情。这时可以用 NavigationPath 管理导航路径。

struct ArticleHomeView: View {
    @State private var path = NavigationPath()

    let articles: [Article]

    var body: some View {
        NavigationStack(path: $path) {
            List(articles) { article in
                Button(article.title) {
                    path.append(article)
                }
            }
            .navigationDestination(for: Article.self) { article in
                ArticleDetailView(article: article)
            }
            .navigationTitle("文章")
        }
    }
}

path.append(article) 表示向导航栈中压入一个页面。返回时，系统会从路径中移除对应项。

入门阶段不需要一开始就使用 NavigationPath。如果只是列表点击进详情，优先使用 NavigationLink。

常见误区#

1. 列表项没有稳定 id#

不要为了省事用数组下标当作长期稳定 id。数据插入、删除或排序后，下标会变化，可能导致列表刷新异常。

更推荐模型本身提供稳定标识：

struct Article: Identifiable {
    let id: UUID
    let title: String
}

2. 把所有逻辑都写进 List#

List 只应该负责展示列表结构。加载、错误、空状态、数据请求更适合放在外层状态判断或 ViewModel 中。

3. 每一行写得太复杂#

如果列表行超过十几行代码，就应该考虑拆成独立 View。列表页重点是组织数据流和导航关系，不应该被行样式淹没。

4. 滥用 NavigationPath#

NavigationPath 适合程序化导航和复杂路径管理。普通列表跳详情，用 NavigationLink 就够了。过早引入路径管理，会让入门代码变复杂。

5. 忘记 NavigationStack#

NavigationLink 通常需要放在 NavigationStack 中才能得到完整的导航行为和标题栏。列表页如果需要跳转，先检查外层是否有 NavigationStack。

6. 在 onAppear 中重复触发分页#

列表行的 onAppear 可能触发多次。分页时一定要在 ViewModel 里加 isLoadingMore 或 hasMore 判断，避免重复请求。

和 Jetpack Compose 的类比#

如果有 Compose 经验，可以先这样建立直觉：

Jetpack Compose SwiftUI 说明
LazyColumn List / LazyVStack 展示集合数据
items(...) ForEach 遍历数据生成行
NavHost NavigationStack 导航容器
composable(route) navigationDestination 定义目标页面
navController.navigate(...) NavigationPath.append(...) 程序化跳转
rememberNavController() @State NavigationPath 持有导航状态

这个类比只适合帮助理解，不要直接照搬。SwiftUI 更强调通过值和类型声明导航目标，Compose 更多围绕 route 和 NavController 组织导航。

小结#

SwiftUI 列表和导航的入门重点可以压缩成几句话：

  • 用 List 展示集合数据
  • 用 Identifiable 提供稳定 id
  • 用独立 View 拆分复杂列表行
  • 用状态区分加载、错误、空数据和正常列表
  • 用 NavigationStack 管理导航层级
  • 用 NavigationLink 完成普通列表到详情的跳转
  • 复杂程序化跳转再考虑 NavigationPath
  • 刷新和分页要注意重复触发与状态保护

掌握这些之后，就可以写出大多数常见的列表详情页。后续再继续深入搜索、分页加载、筛选、编辑模式和多级导航。
