对 Android 开发者来说，接手 Objective-C 存量项目的难点通常不是业务逻辑，而是三套陌生表达同时出现：

  • Objective-C 的消息发送语法
  • UIKit 的页面与事件模型
  • Xcode 的工程、依赖和签名体系

最有效的入门方式不是从 C 语言重新学起，而是先建立 Android 与 iOS 的概念映射，再用 Java 语法经验理解 Objective-C，最后通过一个可运行的 UIKit 小项目把知识串起来。

本文的目标不是全面讲解 Objective-C，而是帮助 Android 开发者尽快做到：

  • 看懂常见 Objective-C 业务代码
  • 找到 iOS 应用入口和页面入口
  • 修改一个 UIKit 列表页面
  • 理解 delegate、Block 和 ARC
  • 避开接手老项目时的常见坑

先建立平台映射#

Android 和 iOS 的框架不能完全等价，但下面的映射可以帮助建立第一印象。

Android iOS存量项目 说明
Application AppDelegate、SceneDelegate 应用和场景生命周期
Activity、Fragment UIViewController 页面控制器，不能完全等价
View、ViewGroup UIView UI 基础对象
XML Layout Storyboard、XIB 可视化页面文件
ConstraintLayout Auto Layout 约束布局
RecyclerView UITableView、UICollectionView 列表和网格
RecyclerView.Adapter UITableViewDataSource 提供列表数据
OnClickListener target-action、delegate、Block 事件回调
interface protocol 能力约束
lambda Block 可传递的代码块
AndroidManifest.xml Info.plist、Entitlements 配置和权限声明
applicationId Bundle Identifier 应用唯一标识
Gradle Module Xcode Target 构建单元，语义并不完全相同

这些概念只适合粗略类比。例如 UIViewController 同时参与视图管理、页面生命周期和导航协作，不能简单看作另一个 Activity。

Java与Objective-C语法对照#

Objective-C 建立在 C 语言之上，并加入了对象、消息、协议和运行时机制。维护普通业务代码时，不需要先系统学习 C，可以优先掌握下面这些高频语法。

1. 常用语法速查#

Java Objective-C 说明
String NSString * 字符串对象
int NSInteger、int 整数
boolean BOOL 使用 YES、NO
null nil 空对象引用
new User() [[User alloc] init] 创建并初始化对象
user.update() [user update] 调用实例方法
static 方法 + 类方法 类级别方法
普通成员方法 - 实例方法 对象方法
List<T> NSArray<T *> * 不可变数组
ArrayList<T> NSMutableArray<T *> * 可变数组
Map<K, V> NSDictionary<K, V> * 字典
interface protocol 能力约束
lambda Block 回调代码块
enum NS_ENUM 枚举
this self 当前对象
extends : 类继承
instanceof isKindOfClass: 类型判断
a == b a == b 比较对象引用
a.equals(b) [a isEqual:b] 比较对象内容
try/catch NSError、Block错误参数 普通错误处理方式不同

2. 变量与基础类型#

Java：

String name = "Tom";
int age = 18;
boolean enabled = true;

Objective-C：

NSString *name = @"Tom";
NSInteger age = 18;
BOOL enabled = YES;

Objective-C 对象类型通常带有 *：

NSString *title = @"Objective-C";
User *user = [[User alloc] init];
UIView *contentView = [[UIView alloc] init];

基础类型不带 *：

NSInteger count = 10;
CGFloat width = 100.0;
BOOL loading = NO;

需要把基础类型放进集合时，可以包装为 NSNumber：

NSInteger count = 10;
NSNumber *boxedCount = @(count);
NSArray<NSNumber *> *numbers = @[@1, @2, @3];

存量项目中经常使用下面的方式定义常量：

static NSString * const UserNameKey = @"user_name";
static NSInteger const MaxRetryCount = 3;

它们接近 Java 中的 static final：

private static final String USER_NAME_KEY = "user_name";
private static final int MAX_RETRY_COUNT = 3;

3. 消息发送与方法调用#

Java 通过点语法调用方法：

user.updateName("Tom");

Objective-C 的基本写法是向对象发送消息：

[user updateName:@"Tom"];

多个参数会成为方法名的一部分：

[user updateName:@"Tom" age:18];

方法声明如下：

- (void)updateName:(NSString *)name age:(NSInteger)age;

其中：

  • - 表示实例方法
  • + 表示类方法
  • (void) 是返回值类型
  • updateName: 和 age: 是参数标签

完整的方法名是 updateName:age:。搜索方法实现时，使用包含冒号的完整名称通常更容易找到目标。

Java 方法：

public User findUser(String userId, boolean useCache) {
    // ...
}

Objective-C 声明：

- (nullable User *)findUserWithID:(NSString *)userID
                         useCache:(BOOL)useCache;

调用：

User *user =
    [service findUserWithID:@"1001"
                   useCache:YES];

4. 类方法与实例方法#

Objective-C 使用 - 表示实例方法：

- (void)reloadData;

调用：

[viewController reloadData];

使用 + 表示类方法，接近 Java 的 static 方法：

+ (instancetype)service;

调用：

UserService *service = [UserService service];

5. 对象创建与初始化#

Java：

User user = new User("Tom", 18);

Objective-C：

User *user =
    [[User alloc] initWithName:@"Tom" age:18];

对象创建分为两个步骤：

alloc：分配对象
init：初始化对象

自定义初始化方法：

- (instancetype)initWithName:(NSString *)name
                         age:(NSInteger)age {
    self = [super init];

    if (self) {
        _name = [name copy];
        _age = age;
    }

    return self;
}

不要省略 self = [super init]。父类初始化方法可能返回另一个对象，也可能返回 nil。

项目中也会经常看到工厂方法：

UIColor *color = [UIColor redColor];
NSMutableArray *tasks = [NSMutableArray array];

6. 属性与成员变量#

Java：

public class User {
    private final String userId;
    private String name;
}

Objective-C：

@interface User : NSObject

@property (nonatomic, copy, readonly) NSString *userID;
@property (nonatomic, copy) NSString *name;

@end

读取和修改属性：

NSString *userID = user.userID;
user.name = @"Jerry";

点语法本质上仍然是 getter 和 setter 调用：

NSString *name = [user name];
[user setName:@"Jerry"];

编译器通常会为属性生成以下划线开头的成员变量，例如 _name。初始化阶段经常直接访问成员变量：

_name = [name copy];

普通业务逻辑中通常通过属性访问：

self.name = name;

7. 属性修饰符#

存量项目中经常能看到：

@property (nonatomic, strong) User *user;
@property (nonatomic, copy) NSString *title;
@property (nonatomic, weak) id<UserDelegate> delegate;
@property (nonatomic, assign) NSInteger count;

常用规则如下：

修饰符 常见用途
strong 普通对象的强引用
copy 字符串和Block
weak delegate、避免循环引用
assign 整数、布尔值、枚举
nonatomic 常见的非原子属性访问

字符串通常使用 copy，避免外部传入的可变字符串影响对象内部状态。

8. 字符串#

Objective-C 字符串字面量需要带 @：

NSString *name = @"Tom";
NSString *message =
    [NSString stringWithFormat:@"Hello, %@", name];

常用格式占位符包括：

类型 占位符
Objective-C对象 %@
NSInteger %ld
BOOL %d
double %f

示例：

NSLog(@"name=%@, age=%ld, enabled=%d",
      name,
      (long)age,
      enabled);

判断字符串是否为空：

if (name == nil || name.length == 0) {
    NSLog(@"名称为空");
}

字符串拼接：

NSString *fullName =
    [NSString stringWithFormat:@"%@ %@", firstName, lastName];

9. 相等性比较#

Java 和 Objective-C 的对象相等性比较非常接近。

Java：

if (name1 == name2) {
    // 是否为同一个对象
}

if (name1.equals(name2)) {
    // 字符串内容是否相同
}

Objective-C：

if (name1 == name2) {
    // 是否指向同一个对象
}

if ([name1 isEqualToString:name2]) {
    // 字符串内容是否相同
}

普通对象通常使用 isEqual: 比较语义是否相等：

if ([user1 isEqual:user2]) {
    NSLog(@"两个对象相等");
}

前提是对应类型正确实现了相等性逻辑。

10. nil与判空#

Java：

String nickname = null;
String displayName = nickname != null ? nickname : "Guest";

Objective-C：

NSString *nickname = nil;
NSString *displayName =
    nickname != nil ? nickname : @"Guest";

项目中也可能看到简写：

NSString *displayName = nickname ?: @"Guest";

Objective-C 可以通过 Nullability 标记说明某个对象能否为空：

NS_ASSUME_NONNULL_BEGIN

@interface UserService : NSObject

- (nullable User *)findUserWithID:(NSString *)userID;

@end

NS_ASSUME_NONNULL_END

向 nil 发送普通消息通常不会像 Java 那样立即抛出空指针异常：

User *user = nil;
NSString *name = [user name];

此时 name 仍然是 nil。这能减少部分判空代码，但也可能让错误静默传播，最终表现为页面没有更新或业务流程没有执行。

11. 条件、循环与枚举#

Objective-C 的 if 和 for 与 Java 非常接近：

if (age >= 18 && enabled) {
    NSLog(@"允许进入");
} else {
    NSLog(@"禁止进入");
}

for (Task *task in tasks) {
    NSLog(@"%@", task.title);
}

带索引遍历：

for (NSInteger index = 0; index < tasks.count; index++) {
    Task *task = tasks[index];
    NSLog(@"index=%ld, title=%@", (long)index, task.title);
}

Objective-C 推荐通过 NS_ENUM 定义枚举：

typedef NS_ENUM(NSInteger, TaskState) {
    TaskStateTodo,
    TaskStateDoing,
    TaskStateDone
};

使用 switch：

switch (state) {
    case TaskStateTodo:
        NSLog(@"待处理");
        break;

    case TaskStateDoing:
        NSLog(@"处理中");
        break;

    case TaskStateDone:
        NSLog(@"已完成");
        break;
}

12. 数组与字典#

Java：

List<String> names = new ArrayList<>();
names.add("Tom");
names.add("Jerry");

Objective-C：

NSMutableArray<NSString *> *names =
    [NSMutableArray array];

[names addObject:@"Tom"];
[names addObject:@"Jerry"];

不可变数组可以使用字面量：

NSArray<NSString *> *names = @[@"Tom", @"Jerry"];
NSString *firstName = names[0];

老项目中可能看到等价写法：

NSString *firstName = [names objectAtIndex:0];

字典：

NSDictionary<NSString *, id> *user = @{
    @"name": @"Tom",
    @"age": @18
};

NSString *name = user[@"name"];
NSNumber *age = user[@"age"];

集合不能直接保存 nil。需要表达空值时，可以使用 NSNull：

NSArray *values = @[@"A", [NSNull null], @"B"];

if (values[1] == [NSNull null]) {
    NSLog(@"空值占位");
}

13. 继承与类型判断#

Java：

public class DetailActivity extends Activity {
    @Override
    protected void onCreate(Bundle state) {
        super.onCreate(state);
    }
}

Objective-C：

@interface DetailViewController : UIViewController
@end

@implementation DetailViewController

- (void)viewDidLoad {
    [super viewDidLoad];
}

@end

Objective-C 没有必须书写的 override 关键字。重写方法时，需要确保方法名和参数完全正确。

类型判断：

if ([value isKindOfClass:[User class]]) {
    User *user = (User *)value;
    NSLog(@"%@", user.name);
}
  • isKindOfClass:：包含子类
  • isMemberOfClass:：必须是当前类本身

14. protocol与interface#

Java 接口：

public interface TaskEditorListener {
    void onTaskCreated(Task task);
}

Objective-C 协议：

@protocol TaskEditorDelegate <NSObject>

@required
- (void)didCreateTask:(Task *)task;

@optional
- (void)didCancelEditing;

@end

声明实现协议：

@interface ViewController () <TaskEditorDelegate>
@end

调用可选方法前，应先判断对象是否实现：

if ([self.delegate respondsToSelector:@selector(didCancelEditing)]) {
    [self.delegate didCancelEditing];
}

15. Block与lambda#

Java lambda：

service.loadTasks((tasks, error) -> {
    if (error != null) {
        return;
    }

    System.out.println(tasks.size());
});

Objective-C Block：

[service loadTasksWithCompletion:
    ^(NSArray<Task *> *tasks, NSError *error) {
        if (error != nil) {
            return;
        }

        NSLog(@"任务数量：%lu",
              (unsigned long)tasks.count);
    }];

Block 类型本身比较难读：

void (^completion)(NSArray<Task *> *tasks, NSError *error);

可以通过 typedef 简化：

typedef void (^TaskCompletion)(
    NSArray<Task *> *tasks,
    NSError *error
);

@property (nonatomic, copy) TaskCompletion completion;

Block 属性通常使用 copy。

16. 错误处理#

Java 经常使用异常传递失败：

try {
    String result = loadData();
} catch (Exception error) {
    error.printStackTrace();
}

Objective-C 的普通可恢复错误通常通过 NSError 返回，而不是依赖异常：

NSError *error = nil;

NSData *data =
    [NSJSONSerialization dataWithJSONObject:object
                                    options:0
                                      error:&error];

if (data == nil) {
    NSLog(@"序列化失败：%@", error);
    return;
}

异步操作通常把错误放进 Block 参数：

[service loadUserWithCompletion:
    ^(User *user, NSError *error) {
        if (error != nil) {
            NSLog(@"加载失败：%@", error);
            return;
        }

        NSLog(@"用户：%@", user.name);
    }];

@try、@catch 确实存在，但通常用于处理程序异常，不应直接类比为 Java 业务错误处理的主要方式。

17. Category与Selector#

Category 可以给已有类增加方法。文件名通常为 类名+分类名。

NSString+Validation.h：

@interface NSString (Validation)

- (BOOL)isValidPhoneNumber;

@end

NSString+Validation.m：

@implementation NSString (Validation)

- (BOOL)isValidPhoneNumber {
    return self.length == 11;
}

@end

调用：

BOOL valid = [phoneNumber isValidPhoneNumber];

UIKit 的 target-action 经常使用 Selector：

[button addTarget:self
           action:@selector(onButtonClick:)
 forControlEvents:UIControlEventTouchUpInside];

对应方法：

- (void)onButtonClick:(UIButton *)sender {
    NSLog(@"按钮被点击");
}

@selector(onButtonClick:) 表示带一个参数的方法，末尾的冒号不能省略。如果出现 unrecognized selector sent to instance，应检查方法名、冒号数量和目标对象的运行时类型。

理解Objective-C文件#

常见文件类型如下：

文件 作用
.h 类、方法和属性声明
.m Objective-C 实现
.mm Objective-C++ 实现
.storyboard 多页面可视化 UI
.xib 单个页面或组件 UI
.plist 应用和模块配置
.xcworkspace 包含多个工程的工作区

Objective-C 类通常拆成 .h 和 .m 两个文件。

以待办模型为例。

Task.h：

#import <Foundation/Foundation.h>

NS_ASSUME_NONNULL_BEGIN

@interface Task : NSObject

@property (nonatomic, copy) NSString *title;
@property (nonatomic, assign, getter=isCompleted) BOOL completed;

- (instancetype)initWithTitle:(NSString *)title;

@end

NS_ASSUME_NONNULL_END

Task.m：

#import "Task.h"

@implementation Task

- (instancetype)initWithTitle:(NSString *)title {
    self = [super init];

    if (self) {
        _title = [title copy];
        _completed = NO;
    }

    return self;
}

@end

@interface 声明类及其公开能力，@implementation 编写具体实现。页面内部使用的属性和方法，通常放在 .m 文件中的匿名扩展里，不必全部暴露到 .h 文件。

UIKit页面与Android页面#

1. 页面生命周期#

UIViewController 是 UIKit 项目中最常见的页面控制器。

Android Activity / Fragment UIViewController
onCreate、onViewCreated viewDidLoad
onStart viewWillAppear:
onResume viewDidAppear:
onPause viewWillDisappear:
onStop viewDidDisappear:

这只是便于理解的近似映射，生命周期触发条件并不完全相同。

页面初始化通常写在：

- (void)viewDidLoad {
    [super viewDidLoad];
    self.view.backgroundColor = [UIColor systemBackgroundColor];
}

viewDidLoad 适合执行视图初始化。每次页面显示都需要执行的逻辑，可以根据场景放到 viewWillAppear: 或 viewDidAppear:。

2. 页面导航#

Android 常通过 Intent 或 Navigation Component 跳转页面。UIKit 存量项目中常见两种方式。

压入导航栈：

[self.navigationController pushViewController:detailController
                                     animated:YES];

模态展示：

[self presentViewController:detailController
                   animated:YES
                 completion:nil];

看到页面跳转代码时，先确认当前页面是否位于 UINavigationController 中。

实战：实现一个待办列表#

下面通过一个待办列表串联 Objective-C、UIKit 和列表事件，功能包括：

  • 展示待办列表
  • 添加待办
  • 点击切换完成状态

创建一个 UIKit + Objective-C 工程，并将初始 ViewController 嵌入 UINavigationController。项目需要下面几个文件：

Task.h
Task.m
ViewController.h
ViewController.m

1. 声明页面内部状态#

ViewController.h 保持简单：

#import <UIKit/UIKit.h>

@interface ViewController : UIViewController
@end

在 ViewController.m 中声明内部属性：

#import "ViewController.h"
#import "Task.h"

@interface ViewController () <UITableViewDataSource, UITableViewDelegate>

@property (nonatomic, strong) UITableView *tableView;
@property (nonatomic, strong) NSMutableArray<Task *> *tasks;

@end

匿名扩展中的属性可以理解为页面的私有成员。UITableViewDataSource 接近 RecyclerView.Adapter 的数据提供职责，UITableViewDelegate 负责部分交互和展示行为。

2. 初始化页面#

@implementation ViewController

- (void)viewDidLoad {
    [super viewDidLoad];

    self.title = @"待办事项";
    self.view.backgroundColor = [UIColor systemBackgroundColor];

    self.tasks = [@[
        [[Task alloc] initWithTitle:@"运行现有工程"],
        [[Task alloc] initWithTitle:@"找到首页入口"]
    ] mutableCopy];

    self.navigationItem.rightBarButtonItem =
        [[UIBarButtonItem alloc]
            initWithBarButtonSystemItem:UIBarButtonSystemItemAdd
            target:self
            action:@selector(addTask)];

    [self setupTableView];
}

target-action 可以类比 Android 的点击监听器：

target:self
action:@selector(addTask)

表示按钮点击后向 self 发送 addTask 消息。

3. 创建UITableView#

- (void)setupTableView {
    UITableView *tableView =
        [[UITableView alloc] initWithFrame:CGRectZero
                                     style:UITableViewStylePlain];

    tableView.translatesAutoresizingMaskIntoConstraints = NO;
    tableView.dataSource = self;
    tableView.delegate = self;

    [self.view addSubview:tableView];

    [NSLayoutConstraint activateConstraints:@[
        [tableView.topAnchor
            constraintEqualToAnchor:self.view.safeAreaLayoutGuide.topAnchor],
        [tableView.leadingAnchor
            constraintEqualToAnchor:self.view.leadingAnchor],
        [tableView.trailingAnchor
            constraintEqualToAnchor:self.view.trailingAnchor],
        [tableView.bottomAnchor
            constraintEqualToAnchor:self.view.bottomAnchor]
    ]];

    self.tableView = tableView;
}

这段代码接近 Android 中创建 View、设置 LayoutParams、添加到父容器并设置 Adapter。

4. 提供列表数据#

- (NSInteger)tableView:(UITableView *)tableView
 numberOfRowsInSection:(NSInteger)section {
    return self.tasks.count;
}

- (UITableViewCell *)tableView:(UITableView *)tableView
         cellForRowAtIndexPath:(NSIndexPath *)indexPath {
    static NSString *identifier = @"TaskCell";

    UITableViewCell *cell =
        [tableView dequeueReusableCellWithIdentifier:identifier];

    if (cell == nil) {
        cell = [[UITableViewCell alloc]
            initWithStyle:UITableViewCellStyleDefault
          reuseIdentifier:identifier];
    }

    Task *task = self.tasks[indexPath.row];

    cell.textLabel.text = task.title;
    cell.accessoryType = task.isCompleted
        ? UITableViewCellAccessoryCheckmark
        : UITableViewCellAccessoryNone;

    return cell;
}

可以粗略理解为：

  • numberOfRowsInSection：接近 Adapter 的 getItemCount
  • cellForRowAtIndexPath：接近 onCreateViewHolder 与 onBindViewHolder 的组合

5. 处理点击事件#

- (void)tableView:(UITableView *)tableView
 didSelectRowAtIndexPath:(NSIndexPath *)indexPath {
    Task *task = self.tasks[indexPath.row];
    task.completed = !task.isCompleted;

    [tableView reloadRowsAtIndexPaths:@[indexPath]
                     withRowAnimation:UITableViewRowAnimationAutomatic];

    [tableView deselectRowAtIndexPath:indexPath animated:YES];
}

didSelectRowAtIndexPath 来自 UITableViewDelegate，接近列表项点击回调。

6. 添加待办#

- (void)addTask {
    UIAlertController *alert =
        [UIAlertController alertControllerWithTitle:@"新建待办"
                                            message:nil
                                     preferredStyle:UIAlertControllerStyleAlert];

    [alert addTextFieldWithConfigurationHandler:
        ^(UITextField *textField) {
            textField.placeholder = @"输入待办内容";
        }];

    __weak typeof(self) weakSelf = self;
    __weak UIAlertController *weakAlert = alert;

    UIAlertAction *cancelAction =
        [UIAlertAction actionWithTitle:@"取消"
                                 style:UIAlertActionStyleCancel
                               handler:nil];

    UIAlertAction *addAction =
        [UIAlertAction actionWithTitle:@"添加"
                                 style:UIAlertActionStyleDefault
                               handler:^(UIAlertAction *action) {
            __strong typeof(weakSelf) strongSelf = weakSelf;
            NSString *title = weakAlert.textFields.firstObject.text;

            if (strongSelf == nil || title.length == 0) {
                return;
            }

            Task *task = [[Task alloc] initWithTitle:title];
            [strongSelf.tasks addObject:task];
            [strongSelf.tableView reloadData];
        }];

    [alert addAction:cancelAction];
    [alert addAction:addAction];

    [self presentViewController:alert animated:YES completion:nil];
}

@end

运行后，可以点击右上角的加号添加待办，点击列表项切换完成状态。这个小项目已经覆盖了对象创建、属性、集合、协议、Block、弱引用和 UIKit 生命周期。

ARC与内存管理#

1. ARC不等于没有内存问题#

Objective-C 项目通常通过 ARC 管理引用计数，但 ARC 不会自动解决循环引用。

下面的代码可能形成循环引用：

self.completion = ^{
    [self finishLoading];
};

引用关系为：

self -> completion Block -> self

常见处理方式：

__weak typeof(self) weakSelf = self;

self.completion = ^{
    __strong typeof(weakSelf) strongSelf = weakSelf;

    if (strongSelf == nil) {
        return;
    }

    [strongSelf finishLoading];
};

并不是所有 Block 中的 self 都会导致泄漏。是否形成循环引用，取决于 Block 是否被 self 或其持有对象长期保存。

2. 检查老项目是否启用ARC#

如果老代码中出现下面的调用：

retain
release
autorelease

不要直接删除。Objective-C 支持按文件关闭 ARC，一个工程中可能同时存在 ARC 文件和通过 -fno-objc-arc 管理的旧文件。

应先检查 Target 的 Build Settings 和 Compile Sources 配置，再决定如何修改内存管理代码。

接手存量工程的推荐顺序#

1. 先跑通原始工程#

在修改代码前先记录基线：

  • 使用哪个 Xcode 版本
  • 打开 .xcworkspace 还是 .xcodeproj
  • 使用哪个 Scheme 和 Target
  • 依赖通过 CocoaPods、Swift Package Manager 还是其他方式管理
  • 模拟器能否正常启动
  • 原始工程是否已经存在编译警告或崩溃

如果项目使用 CocoaPods，通常应该打开 .xcworkspace。误开 .xcodeproj 是常见的依赖缺失原因。

2. 找应用入口#

优先查看：

main.m
AppDelegate.m
SceneDelegate.m

确认：

  • UIWindow 在哪里创建
  • 根控制器是什么
  • 首页通过 Storyboard 还是代码加载
  • 启动阶段初始化了哪些服务

3. 找页面入口#

搜索目标页面的 UIViewController，然后确认：

  • 页面来自 Storyboard、XIB 还是纯代码
  • 有哪些 IBOutlet 和 IBAction
  • 页面在哪个生命周期方法加载数据
  • 页面通过 push 还是 present 打开

Storyboard、XIB 中的连线失效时，运行阶段可能出现找不到 Key Value Coding 属性的崩溃。重命名属性后，需要同步检查可视化文件中的连接。

4. 沿数据流阅读#

一个列表页面可以沿下面的顺序阅读：

viewDidLoad
-> 发起请求
-> Block或delegate回调
-> 更新Model
-> reloadData
-> cellForRowAtIndexPath

这和 Android 中沿着 ViewModel、Repository、Adapter 阅读数据流的思路类似。

5. 第一次只做小改动#

第一次修改尽量选择容易验证的内容：

  • 修改一段展示文案
  • 增加一条日志
  • 调整一个列表字段
  • 修复一个明确的判空问题
  • 增加一个简单按钮事件

先跑通编译、调试和提交流程，再处理架构改造或大范围重构。

Android开发者常见误区#

1. 把UIViewController完全当成Activity#

两者只适合做粗略类比。导航、视图加载、页面复用和生命周期触发条件都有差异。

修改生命周期代码前，应先通过断点确认实际调用顺序。

2. 把UITableView当成RecyclerView直接套用#

UITableViewDataSource 同时承担部分 Adapter 职责，但 Cell 注册、复用、代理回调和高度计算方式并不完全相同。

先理解现有页面的 dataSource 和 delegate，再修改刷新逻辑。

3. 把所有对象属性都声明为strong#

普通对象可以使用 strong，但：

  • 字符串和 Block 通常使用 copy
  • delegate 通常使用 weak
  • 基础类型使用 assign

错误的引用关系可能造成页面退出后仍然无法释放。

4. 认为向nil发送消息永远没有风险#

向 nil 发送普通消息通常不会立即崩溃，但这可能让错误静默传播。

另外，数组越界、访问已经释放的对象、错误的 Selector 和失效的 Storyboard 连线仍然会导致崩溃。

5. 一开始就重构老项目#

存量工程中可能同时存在：

  • Objective-C 与 Swift 混编
  • ARC 与非 ARC 文件
  • Storyboard、XIB 和纯代码页面
  • Category、宏和 Method Swizzling
  • 多个 Target 与不同编译配置

在没有跑通主要流程、测试和发布配置前，不适合大范围迁移或重构。

小结#

Android 开发者接手 Objective-C 存量项目时，可以先抓住四组映射：

Activity / Fragment -> UIViewController
RecyclerView -> UITableView / UICollectionView
interface / listener -> protocol / delegate
lambda -> Block

然后重点掌握：

  • Objective-C 消息发送语法
  • .h 与 .m 的职责
  • UIKit 页面生命周期
  • dataSource、delegate 和 target-action
  • ARC、strong、weak、copy
  • Xcode Target、Scheme、Workspace 和依赖关系

入门阶段不需要立即深入 Objective-C Runtime。先让工程成功运行，从一个页面出发，沿着生命周期、数据请求、回调和列表刷新路径阅读代码。

当你能够独立修改一个页面、处理一次回调并定位一次引用问题时，就已经具备维护普通 Objective-C 业务代码的基础。
