Swift 是 Apple 平台开发的主要语言，常用于 iOS、macOS、watchOS 和 visionOS 应用开发。对已经熟悉 Kotlin 的开发者来说，Swift 的入门难点通常不在“变量、函数、条件判断”这些基础语法，而在几组容易误判的概念：Optional、值类型、协议、闭包、错误处理和并发模型。

这篇文章不按零基础教程展开，而是从 Kotlin 开发者的视角，梳理 Swift 中最值得优先掌握的基础能力。

为什么 Kotlin 开发者学 Swift 不难#

Kotlin 和 Swift 都是现代静态类型语言，很多设计目标相似：

  • 都支持类型推断
  • 都强调空值安全
  • 都有 lambda / closure
  • 都支持泛型
  • 都有扩展能力
  • 都适合写简洁的业务代码

例如，Kotlin 中的 val、var：

val name = "Tom"
var age = 18

age = 19

Swift 中对应的是 let、var：

let name = "Tom"
var age = 18

age = 19

从语法观感上看，两者差异不大。但 Swift 更强调值类型、协议组合和编译期约束，这些地方需要单独适应。

语法对照速查#

下面这张表可以作为初学 Swift 时的快速参照。

Kotlin Swift 说明
val let 不可重新赋值
var var 可以重新赋值
String? String? 可空 / 可选值
null nil 空值
?: ?? 空值默认值
fun func 函数声明
interface protocol 能力约束
class class 引用类型
data class struct 只能粗略类比，语义不同
lambda closure 可传递代码块
suspend async 异步函数
try/catch do/try/catch 错误处理
Dispatchers.Main MainActor 只能类比，机制不同

这张表只能帮助建立直觉，不能完全等价迁移。Swift 中有些概念和 Kotlin 看起来相似，但底层语义不同。

变量、类型与 Optional#

Swift 支持类型推断：

let title = "Swift"
let count = 10
let enabled = true

也可以显式声明类型：

let title: String = "Swift"
let count: Int = 10
let price: Double = 19.9
let enabled: Bool = true

数组和字典的写法如下：

let names: [String] = ["Tom", "Jerry"]
let scores: [String: Int] = [
    "Tom": 90,
    "Jerry": 85
]

1. Optional 类似 Kotlin nullable#

Swift 的 Optional 和 Kotlin 的 nullable 类型很像。

Swift：

var nickname: String? = nil
nickname = "Alice"

Kotlin：

var nickname: String? = null
nickname = "Alice"

Swift 中不能直接把 String? 当成 String 使用，需要先解包。

if let name = nickname {
    print(name)
}

这和 Kotlin 的安全调用不完全一样，但目标类似，都是为了避免空值崩溃。

nickname?.let { name ->
    println(name)
}

2. guard let 更适合提前退出#

iOS 项目中经常使用 guard let 处理必要参数。

func printNickname(_ nickname: String?) {
    guard let name = nickname else {
        return
    }

    print(name)
}

它适合表达“如果没有这个值，后面的逻辑就不应该继续执行”。

3. 不要滥用强制解包#

Swift 可以用 ! 强制解包：

print(nickname!)

但如果 nickname 实际是 nil，程序会直接崩溃。对 Kotlin 开发者来说，可以把它理解成一种比 !! 更需要谨慎的写法。

入门阶段建议优先使用：

if let name = nickname {
    print(name)
}

let displayName = nickname ?? "Guest"

函数与参数标签#

Swift 使用 func 声明函数。

func add(_ a: Int, _ b: Int) -> Int {
    return a + b
}

let result = add(1, 2)

这里的 _ 表示调用时省略外部参数名。

如果不写 _，调用时需要带参数名：

func greet(name: String, age: Int) {
    print("\(name), \(age)")
}

greet(name: "Tom", age: 18)

这是 Swift 和 Kotlin 差异比较明显的地方。Swift 很重视调用点的可读性，所以参数标签是 API 设计的一部分。

比如：

func move(from start: Int, to end: Int) {
    print("move from \(start) to \(end)")
}

move(from: 1, to: 10)

调用代码读起来接近自然语言。写 Swift API 时，不只要考虑函数内部怎么实现，也要考虑调用时是否清楚。

struct、class 与值语义#

Swift 中 struct 和 class 都可以定义属性和方法，但语义不同。

  • struct 是值类型
  • class 是引用类型
  • class 支持继承
  • struct 不支持继承
  • Swift 标准库中的 String、Array、Dictionary 都是结构体
struct User {
    let id: Int
    var name: String
}

var user1 = User(id: 1, name: "Tom")
var user2 = user1

user2.name = "Jerry"

print(user1.name) // Tom
print(user2.name) // Jerry

user2 修改后不会影响 user1。

class 则不同：

class Counter {
    var value = 0
}

let c1 = Counter()
let c2 = c1

c2.value = 10

print(c1.value) // 10

c1 和 c2 指向同一个对象。

对 Kotlin 开发者来说，最容易踩的坑是把 Swift struct 简单等同于 Kotlin data class。它们都适合表达数据，但 Swift struct 是值类型，这会影响赋值、传参和状态更新。

实际 iOS 开发中可以先遵循这个判断：

  • 数据模型优先用 struct
  • 配置、状态快照优先用 struct
  • 需要共享状态时考虑 class
  • 需要继承或引用生命周期时考虑 class

protocol、extension 与泛型#

Swift 的 protocol 类似 Kotlin 的 interface，用于定义一组能力。

protocol IdentifiableItem {
    var id: Int { get }
}

struct Article: IdentifiableItem {
    let id: Int
    let title: String
}

extension 可以给已有类型添加能力。

extension String {
    var isNotEmptyText: Bool {
        return !isEmpty
    }
}

let name = "Swift"
print(name.isNotEmptyText)

这和 Kotlin extension function 很接近：

fun String.isNotEmptyText(): Boolean {
    return this.isNotEmpty()
}

Swift 的协议和扩展经常组合使用。比如可以给所有符合某个协议的类型提供默认实现：

protocol Displayable {
    var title: String { get }
    func displayText() -> String
}

extension Displayable {
    func displayText() -> String {
        return "Title: \(title)"
    }
}

struct Book: Displayable {
    let title: String
}

let book = Book(title: "Swift Guide")
print(book.displayText())

泛型用于编写和具体类型无关的代码：

func first<T>(_ items: [T]) -> T? {
    return items.first
}

let name = first(["Tom", "Jerry"])
let number = first([1, 2, 3])

泛型也可以加协议约束：

func printTitle<T: Displayable>(_ value: T) {
    print(value.title)
}

SwiftUI 中会大量出现协议、泛型和扩展。入门时不必急着完全理解所有类型推导，先能读懂“某个类型需要满足某个协议”就够了。

闭包：SwiftUI 和异步代码的基础#

Swift 的闭包类似 Kotlin lambda，可以作为参数传递。

let numbers = [1, 2, 3]

let doubled = numbers.map { value in
    value * 2
}

可以简写为：

let doubled = numbers.map { $0 * 2 }

过滤数组：

let evenNumbers = numbers.filter { $0 % 2 == 0 }

排序：

let sorted = numbers.sorted { a, b in
    a > b
}

Swift 里有一个很常见的写法叫尾随闭包。比如：

performRequest {
    print("finished")
}

如果函数最后一个参数是闭包，就可以把闭包写在括号外面。这种写法在 SwiftUI 中极其常见：

Button("Load") {
    print("button tapped")
}

这里的点击事件就是一个闭包。

错误处理：throws、try、do-catch#

Swift 使用 throws 声明可能抛出错误的函数。

enum NetworkError: Error {
    case invalidURL
    case emptyData
}

func request() throws -> String {
    throw NetworkError.invalidURL
}

调用时使用 try：

do {
    let data = try request()
    print(data)
} catch {
    print("request failed: \(error)")
}

如果不关心具体错误，可以用 try?：

let data = try? request()

try? 会把返回值转成 Optional。如果函数抛错，结果就是 nil。

这很方便，但不要滥用。调试网络请求、文件读写、JSON 解析时，优先使用 do-catch，否则错误原因会被隐藏。

并发：async/await、Task、MainActor#

Swift 现代并发的核心是 async/await。

func loadUser() async throws -> User {
    return User(id: 1, name: "Tom")
}

调用异步函数时需要 await：

Task {
    do {
        let user = try await loadUser()
        print(user.name)
    } catch {
        print(error)
    }
}

Task 常用于从同步上下文进入异步上下文，例如按钮点击后发起网络请求。

func onTapLoadButton() {
    Task {
        let user = try await loadUser()
        print(user)
    }
}

MainActor 用于隔离需要在主线程执行的代码。UI 状态更新通常应该在 MainActor 上进行。

@MainActor
final class UserViewModel: ObservableObject {
    @Published var name = ""

    func load() async {
        name = "Tom"
    }
}

如果用 Kotlin 类比，可以粗略理解为：MainActor 和 Dispatchers.Main 都和主线程 UI 更新有关。但 MainActor 是 Swift 并发模型中的 actor 隔离机制，不只是线程切换工具。

入门阶段先记住三点：

  • 耗时操作适合放进异步函数
  • 调用异步函数时使用 await
  • 更新 UI 状态时注意 MainActor

一个贯穿示例#

下面用一个简单的用户加载场景，把 struct、Optional、protocol、async throws 和 MainActor 串起来。

先定义模型：

struct User {
    let id: Int
    let name: String
    let nickname: String?
}

定义一个协议，表示具备加载用户的能力：

protocol UserLoading {
    func loadUser(id: Int) async throws -> User
}

实现一个服务：

struct UserService: UserLoading {
    func loadUser(id: Int) async throws -> User {
        return User(id: id, name: "Tom", nickname: nil)
    }
}

定义 ViewModel：

@MainActor
final class UserViewModel: ObservableObject {
    @Published var displayName = ""
    @Published var errorMessage: String?

    private let service: UserLoading

    init(service: UserLoading = UserService()) {
        self.service = service
    }

    func load() {
        Task {
            do {
                let user = try await service.loadUser(id: 1)
                displayName = user.nickname ?? user.name
            } catch {
                errorMessage = "加载用户失败"
            }
        }
    }
}

这个例子里有几个 Swift 常见点：

  • User 用 struct 表达数据
  • nickname 用 String? 表达可能为空
  • UserLoading 用 protocol 抽象能力
  • loadUser 用 async throws 表达异步且可能失败
  • UserViewModel 用 @MainActor 约束 UI 状态更新
  • ?? 用于处理 Optional 默认值

这类代码结构在 iOS 项目中很常见。

Swift 与 SwiftUI 的关系#

Swift 是语言，SwiftUI 是用 Swift 构建的声明式 UI 框架。二者不是同一个层面的东西。

SwiftUI 代码看起来很简洁：

struct ContentView: View {
    var body: some View {
        VStack {
            Text("Hello")
            Button("Tap") {
                print("Tapped")
            }
        }
    }
}

但这段代码背后同时涉及：

  • struct：视图通常是值类型
  • protocol：View 是协议
  • some View：不透明返回类型
  • 闭包：VStack {} 和 Button {} 都使用闭包
  • 声明式 UI：界面由状态推导出来

所以 SwiftUI 不建议塞进 Swift 基础文章里详细讲。更合理的安排是：

  • Swift 基础文章讲语言能力
  • SwiftUI 文章讲 View、状态、布局、列表、导航和生命周期
  • SwiftUI 文章中再解释这些语言能力如何服务于声明式 UI

换句话说，Swift 是地基，SwiftUI 是建在这个地基上的 UI 框架。

Kotlin 开发者常见误区#

1. 把 Optional 当普通值用#

看到 String? 时，要立刻意识到它不是 String。先处理空值，再进入业务逻辑。

2. 滥用强制解包#

value! 很像是在告诉编译器“相信我”。但运行时一旦是 nil，就会崩溃。除非非常确定，否则不要用它解决编译错误。

3. 把 struct 当成 data class#

Swift struct 是值类型。它可以表达数据，但不等同于 Kotlin data class。赋值、传参和状态更新时要注意复制语义。

4. 忽略参数标签#

Swift 的参数标签会影响调用点的可读性。不要只从函数内部看 API，也要看调用代码是否清楚。

5. 用 try? 吞掉错误#

try? 很方便，但会丢失错误原因。调试阶段和关键业务逻辑里，优先使用 do-catch。

6. 把 MainActor 简单理解成主线程工具#

MainActor 和主线程 UI 更新有关，但它属于 Swift 并发隔离模型。后续深入并发时，需要把它当成 actor 机制的一部分理解。

推荐学习路线#

如果已经有 Kotlin 经验，可以按下面顺序学习 Swift：

  1. 熟悉 let、var、基础类型和字符串插值
  2. 重点理解 Optional、if let、guard let、??
  3. 掌握函数参数标签
  4. 区分 struct 与 class
  5. 学习 protocol、extension 和泛型约束
  6. 熟悉闭包、尾随闭包和 $0
  7. 学会 throws、try、do-catch
  8. 学习 async/await、Task、MainActor
  9. 再进入 SwiftUI，用一个小 App 串联这些语法

官方资料可以优先看：

  • The Swift Programming Language
  • Develop in Swift

小结#

Kotlin 开发者学习 Swift，真正需要转换的是语言习惯，而不是从零理解编程概念。

优先掌握几条主线就够了：用 Optional 处理空值，用 struct 表达值类型数据，用 protocol 和 extension 组织能力，用闭包传递行为，用 throws 表达失败，用 async/await 和 MainActor 处理异步与 UI 状态。

SwiftUI 建议单独成文。Swift 基础文章负责把语言特性讲清楚，SwiftUI 文章再解释这些特性如何组合成声明式 UI。
