SwiftUI基础入门：从状态驱动界面开始

SwiftUI 是 Apple 提供的声明式 UI 框架。和 UIKit 里手动创建控件、修改属性、维护页面层级不同，SwiftUI 更强调“界面是状态的函数”：状态变了，界面自动重新计算并刷新。

如果已经有 Kotlin、Android 或 Compose 经验，可以把 SwiftUI 先理解为 Apple 平台上的声明式 UI 方案。它和 Jetpack Compose 很像，都不是简单的 XML 或 View 替代品，而是一套围绕状态、组合和数据流设计的 UI 编程模型。

SwiftUI 解决什么问题#

在 UIKit 中，常见写法是先拿到控件，再手动更新控件状态。

label.text = user.name
button.isEnabled = !isLoading
loadingView.isHidden = !isLoading

这种方式本身没有问题，但页面复杂后，状态和 UI 很容易分散在多个地方。比如加载中、加载成功、加载失败、空列表、按钮是否可点，都需要开发者手动维护。

SwiftUI 的思路是反过来：先描述不同状态下界面应该长什么样，然后让框架根据状态变化刷新界面。

struct ContentView: View {
    @State private var isLoading = false

    var body: some View {
        VStack {
            if isLoading {
                ProgressView()
            } else {
                Text("加载完成")
            }

            Button("加载") {
                isLoading = true
            }
        }
    }
}

这里没有手动隐藏 ProgressView，也没有手动修改 Text。只要 isLoading 变化，body 会重新计算，界面会随之更新。

View 是什么#

SwiftUI 中的页面和组件通常是一个 struct，并且遵守 View 协议。

struct ContentView: View {
    var body: some View {
        Text("Hello SwiftUI")
    }
}

这里有几个关键点：

  • ContentView 是结构体，不是类
  • View 是协议
  • body 描述界面内容
  • some View 表示返回某种具体的 View，但调用方不需要知道具体类型

对刚入门的人来说，不需要一开始深挖 some View 的类型系统细节。先记住：body 里写的是这个 View 当前状态下应该展示的界面。

组合界面#

SwiftUI 不是通过继承创建复杂页面，而是通过组合小 View。

struct UserHeaderView: View {
    let name: String
    let subtitle: String

    var body: some View {
        VStack(alignment: .leading) {
            Text(name)
                .font(.headline)

            Text(subtitle)
                .font(.subheadline)
                .foregroundStyle(.secondary)
        }
    }
}

使用时直接组合：

struct ProfileView: View {
    var body: some View {
        UserHeaderView(
            name: "Tom",
            subtitle: "iOS Developer"
        )
    }
}

这种方式和 Compose 的 Composable 函数很接近：把界面拆成小块，再通过参数传入数据。

常见布局容器#

SwiftUI 中最常用的布局容器有三个：

  • VStack：垂直排列
  • HStack：水平排列
  • ZStack：层叠排列
VStack(alignment: .leading, spacing: 12) {
    Text("标题")
        .font(.title)

    HStack {
        Text("作者")
        Spacer()
        Text("2026-07-08")
    }

    Text("正文内容")
}
.padding()

Spacer() 用来占据剩余空间，常用于把内容推到两侧。

HStack {
    Text("左侧")
    Spacer()
    Text("右侧")
}

SwiftUI 的布局不是直接设置 x、y 坐标，而是通过容器、对齐、间距和修饰符组合出来。

Modifier 是什么#

SwiftUI 通过 modifier 修改 View 的样式或行为。

Text("Hello")
    .font(.title)
    .foregroundStyle(.blue)
    .padding()
    .background(.gray.opacity(0.1))
    .cornerRadius(8)

需要注意的是，modifier 通常会返回一个新的 View，而不是原地修改旧 View。这和 Swift 的值类型思想一致。

modifier 的顺序会影响结果：

Text("Hello")
    .padding()
    .background(.yellow)

和下面这个效果不一样：

Text("Hello")
    .background(.yellow)
    .padding()

第一种是先加内边距，再给整体加背景；第二种是先给文本区域加背景，再加外部间距。

状态驱动界面#

SwiftUI 最核心的概念是状态驱动界面。界面不是被手动修改出来的，而是由状态推导出来的。

struct CounterView: View {
    @State private var count = 0

    var body: some View {
        VStack(spacing: 16) {
            Text("Count: \(count)")

            Button("加一") {
                count += 1
            }
        }
    }
}

@State 表示这个状态由当前 View 持有。当 count 改变时，SwiftUI 会重新计算 body，并更新界面。

可以先记住一个判断：

  • 当前 View 自己使用、自己修改的小状态，用 @State
  • 父 View 传给子 View，并希望子 View 修改，用 @Binding
  • 页面级业务状态，通常放进 ViewModel

@State：View 自己持有状态#

@State 适合简单的本地状态，比如开关、输入框内容、选中状态。

struct LoginFormView: View {
    @State private var username = ""
    @State private var password = ""

    var body: some View {
        VStack(spacing: 12) {
            TextField("用户名", text: $username)
            SecureField("密码", text: $password)

            Button("登录") {
                print(username, password)
            }
            .disabled(username.isEmpty || password.isEmpty)
        }
        .padding()
    }
}

这里 $username 不是普通的字符串，而是一个绑定。TextField 可以通过它读取并修改 username。

@Binding：把状态传给子 View#

如果状态在父 View 中，但子 View 需要修改它，就使用 @Binding。

struct FavoriteButton: View {
    @Binding var isFavorite: Bool

    var body: some View {
        Button {
            isFavorite.toggle()
        } label: {
            Image(systemName: isFavorite ? "star.fill" : "star")
        }
    }
}

父 View 中持有状态：

struct ArticleView: View {
    @State private var isFavorite = false

    var body: some View {
        FavoriteButton(isFavorite: $isFavorite)
    }
}

这里的状态所有权在 ArticleView，FavoriteButton 只是拿到一个可读写的引用关系。

列表与条件渲染#

SwiftUI 中列表通常使用 List 和 ForEach。

struct Todo: Identifiable {
    let id: UUID
    let title: String
    var done: Bool
}

struct TodoListView: View {
    let todos: [Todo]

    var body: some View {
        List(todos) { todo in
            HStack {
                Image(systemName: todo.done ? "checkmark.circle.fill" : "circle")
                Text(todo.title)
            }
        }
    }
}

Identifiable 用来告诉 SwiftUI 每一项的唯一标识。列表刷新时，SwiftUI 需要根据 id 判断哪些元素新增、删除或变化。

条件渲染也很常见：

if todos.isEmpty {
    ContentUnavailableView("暂无任务", systemImage: "tray")
} else {
    TodoListView(todos: todos)
}

不要把所有状态都塞进一个巨大 View。列表项、空状态、错误状态都可以拆成独立 View。

页面级状态：ViewModel#

简单状态可以放在 View 里，但真实页面通常会有网络请求、加载状态、错误信息和业务逻辑。这时更适合放到 ViewModel。

struct User: Identifiable {
    let id: Int
    let name: String
}

@MainActor
final class UserListViewModel: ObservableObject {
    @Published var users: [User] = []
    @Published var isLoading = false
    @Published var errorMessage: String?

    func loadUsers() async {
        isLoading = true
        errorMessage = nil

        do {
            users = [
                User(id: 1, name: "Tom"),
                User(id: 2, name: "Jerry")
            ]
        } catch {
            errorMessage = "加载用户失败"
        }

        isLoading = false
    }
}

在 View 中使用：

struct UserListPage: View {
    @StateObject private var viewModel = UserListViewModel()

    var body: some View {
        List(viewModel.users) { user in
            Text(user.name)
        }
        .overlay {
            if viewModel.isLoading {
                ProgressView()
            }
        }
        .task {
            await viewModel.loadUsers()
        }
    }
}

这里有几个重点：

  • @StateObject 表示当前 View 创建并持有 ViewModel
  • @Published 的属性变化后，界面会刷新
  • .task 适合在 View 出现时启动异步任务
  • @MainActor 确保 UI 状态更新在主 actor 上执行

@StateObject 与 @ObservedObject#

刚开始学 SwiftUI 时，@StateObject 和 @ObservedObject 很容易混淆。

简单判断：

  • View 自己创建对象，用 @StateObject
  • 对象从外部传入，用 @ObservedObject

例如当前页面自己创建 ViewModel：

@StateObject private var viewModel = UserListViewModel()

子 View 接收父 View 传入的对象：

struct UserListContentView: View {
    @ObservedObject var viewModel: UserListViewModel

    var body: some View {
        List(viewModel.users) { user in
            Text(user.name)
        }
    }
}

如果把应该用 @StateObject 的地方写成 @ObservedObject，可能导致 View 重新计算时对象被重新创建，引发状态丢失或重复请求。

SwiftUI 中的常见误区#

1. 把 body 当成只执行一次#

body 会随着状态变化重新计算。不要在 body 里写有副作用的代码，比如发网络请求、写数据库、修改全局状态。

错误示例：

var body: some View {
    loadUsers()
    return Text("Users")
}

异步任务应该放到 .task、按钮事件或 ViewModel 方法里。

2. 状态所有权不清楚#

状态应该有明确归属。谁创建、谁持有、谁修改，要尽量清楚。

  • 本地 UI 状态：@State
  • 父子双向传递：@Binding
  • 页面业务状态：ViewModel
  • 外部注入对象：@ObservedObject

3. 过早深挖复杂类型#

SwiftUI 的类型系统很复杂，some View、泛型、ViewBuilder 会让错误信息看起来很长。入门阶段先把状态、布局、列表、导航和异步任务用熟，再回头理解底层类型会更稳。

4. 用 UIKit 思维手动改 UI#

SwiftUI 中不要想着“找到某个控件然后改属性”。更好的思路是修改状态，让界面根据状态变化自动更新。

和 Jetpack Compose 的类比#

如果有 Android Compose 经验，可以先这样类比：

Jetpack Compose SwiftUI 说明
@Composable View.body 描述 UI
remember @State View 本地状态
MutableState @State / @Binding 状态变化驱动刷新
Column VStack 垂直布局
Row HStack 水平布局
Box ZStack 层叠布局
LazyColumn List / LazyVStack 列表
LaunchedEffect .task 启动异步任务
ViewModel ViewModel + ObservableObject 页面状态承载

这个类比只用于建立直觉。SwiftUI 和 Compose 的生命周期、状态保存、导航和并发模型并不完全一样，不能机械迁移。

小结#

SwiftUI 入门的关键不是记住所有组件，而是先理解“状态驱动界面”这件事。

可以按这个顺序学习：

  1. 用 VStack、HStack、ZStack 组合布局
  2. 用 modifier 调整样式
  3. 用 @State 管理本地状态
  4. 用 @Binding 拆分可复用子 View
  5. 用 List 和 ForEach 展示集合数据
  6. 用 ViewModel 管理页面级状态
  7. 用 .task 和 async/await 处理异步加载
  8. 最后再深入导航、动画、环境值和生命周期

SwiftUI 的学习重点是转变思路：不要手动同步 UI，而是把状态设计清楚，让界面从状态自然推导出来。
