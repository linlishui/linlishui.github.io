工具类型

TypeScript进阶用法

上一篇入门文章已经覆盖了基础类型、函数、对象、interface、type、联合类型和可空处理。继续往下学 TypeScript，重点不是记更多语法，而是学会把类型用在真实代码里：接口响应、状态结构、异步结果和公共函数都应该有清晰的类型边界。 模块导入与文件引用 TypeScript 支持用 export 暴露变量、函数或类型，再用 import 在其他文件中引用： // user.ts export type User = { id: number; name: string; }; export function getUserName(user: User): string { return user.name; } // main.ts import { getUserName, type User } from "./user"; const user: User = { id: 1, name: "Tom", }; console.log(getUserName(user)); 和 Kotlin 按包名导入不同，TypeScript 默认更多是按文件路径导入。"./user" 表示同级目录下的 user.ts，通常可以省略 .ts 后缀。 如果只引用类型，推荐使用 import type： import type { User } from "./user"; 大型项目里也常见路径别名，例如 @/models/user，但这需要在 tsconfig.json 里配置 baseUrl 和 paths。 泛型是什么 泛型可以简单理解成：把类型也作为参数传进去。 它解决的核心问题是：代码逻辑可以复用，但类型信息不能丢。 function wrap<T>(value: T): T[] { return [value]; } const names = wrap("hello"); // string[] const ids = wrap(100); // number[] 如果不用泛型，很容易退回到 any： function wrap(value: any): any[] { return [value]; } 这段代码虽然能运行，但调用方拿不到准确类型提示。 泛型最常见的使用场景是接口响应： type ApiResponse<T> = { code: number; message: string; data: T; }; type User = { id: number; name: string; }; const response: ApiResponse<User> = { code: 0, message: "ok", data: { id: 1, name: "Tom", }, }; 可以先记住一句话：泛型不是为了把类型写复杂，而是为了保留“输入、输出、数据结构之间的类型关系”。 ...
